## 1. Executive Answers to User Inquiries

### Question 1: "S₀ provides no (empty) context? Are we doing both the original method and the Allen method for all of them?"

#### A. Does $S_0$ receive zero context?
**YES, exactly.**  
By fundamental architectural definition, **$S_0$ is the un-augmented parametric control baseline**.
* It has **no retriever**, **no database**, **no knowledge graph**, and **no context stuffing**.
* Its context window payload is literally **0 words** (`context_text = ""`).
* **Why this is critical**:
  1. **In the Original Benchmark (`run_eval.py`)**: It receives only the hypothesis with zero evidence. Because its system prompt instructs it never to guess without evidence, a well-calibrated model responds `"insufficient"` 9 out of 10 times (**90% Abstention**, **10% Accuracy**).
  2. **In the Allen Benchmark (`run_scholarqa_bakeoff.py`)**: It receives an open mechanistic query and is told: *"For every claim, cite the exact literature and provide a VERBATIM quote."* Because it has **0 words of context**, it relies solely on parametric memory. The result is catastrophic hallucination: out of 18 citations generated, **16 were completely fabricated (88.9% Citation Bluffing)**.

#### B. Are both methods applied to all systems?
* **Conceptually**: Yes, both evaluation methodologies represent universal testing standards for scientific AI.
* **Empirically in our automated test runs**:
  * **Original Benchmark (`run_eval.py` / `eval_cached.py`)**: All 5 systems ($S_0, S_1, S_2, S_3, S_{\text{cached}}$) were executed across all 10 canonical textbook hypotheses (`q01`–`q10`).
  * **Allen Benchmark (`run_scholarqa_bakeoff.py`)**: 4 systems ($S_0, S_2, S_3, S_{\text{cached}}$) were executed in the automated 10-query batch script loop. $S_1$ (BM25 Chunker) was evaluated via manual chunk-level quote matching (e.g., in the Question 2 autopsy and LitQA2), but was omitted from the automated 10-query ScholarQA script run because $S_1$ is an unindexed raw sliding-window chunker rather than a structured claim store.

### Architectural Takeaways from Table 1:
1. **$S_0$ Honest Abstention**: With 0 words of context, $S_0$ abstained 90% of the time, proving that under an explicit NLI prompt without retrieval, it refuses to guess.
2. **$S_2$ Retrieval Dominance**: $S_2$ achieved **0.55 Page Recall**—more than double BM25 (0.25) and nearly triple Long Context (0.20)—delivering 70% accuracy within a tight **357-word footprint**.
3. **$S_{\text{cached}}$ Lost-in-the-Middle**: Shoving 50,000 words into Gemini's context resulted in only **0.20 Page Recall**, as attention heads missed critical needle-in-haystack equations buried across 90-page textbook windows.

## 6. Synthesis: Why Both Methods Are Essential

Neither benchmark in isolation tells the complete architectural story:

1. **If you only run the Original Sanity Method (`run_eval.py`)**:
   * You see that $S_1$ (BM25) and $S_2$ (Relational DB) both scored 70.0% Accuracy.
   * You might falsely conclude that BM25 is just as good as a Relational Proposition DB!
2. **When you introduce the Allen Institute Method (`run_scholarqa_bakeoff.py`)**:
   * You immediately discover that BM25’s arbitrary 300-word windows severed quotes in half, causing citation verification failures.
   * You discover that Long Context ($S_{\text{cached}}$) achieves 94% quote accuracy, but costs **139× more tokens** and suffers **74-second latencies**.
   * You confirm that $S_2$ provides the optimal **Pareto trade-off**: highest recall (**0.55**), zero citation bluffing (**0.0%**), and lightning-fast latency (**1.8s**) in under **400 context words**.
